# 05. LLM との進め方

このリポジトリの内容は、Claude（claude.ai）を中心に複数の AI と相談しながら作った方針を整理したもの。

## アーキテクチャ

```
 日々の相談・記録の振り返り        設計のクロスレビュー             ナレッジベース
┌──────────────────┐        ┌──────────────────────┐        ┌──────────────────┐
│ Claude (chat)    │ ─────▶ │ 複数 AI のレポート    │ ─────▶ │ NotebookLM        │
│ ・食事・睡眠の相談 │        │ → Deep Research で統合 │        │ ・結論まとめを保存  │
│ ・週次の振り返り   │        │ → ベース文書を確定     │        │ ・後から検索・質問  │
└──────────────────┘        └──────────────────────┘        └──────────────────┘
                                                                      │
                                                                      ▼
                                                            このリポジトリ（公開版）
```

## やってよかったこと

### 1. 複数 AI の案をクロスレビューさせる

1つの AI の案をそのまま採用しない。

- AI-1 の案：大枠は良いが「30°インクライン必須」「全種目3秒エキセントリック」など断定が強い
- AI-2 の案（Claude）：RIR や膝屈曲種目が入って改善されているが、一部が最初から高ボリューム、年齢など未指定情報を仮定している
- → 3つ目の Deep Research に両方を渡し、**一次研究に照らして断定の強い部分を落とす** 形で統合した

コードレビューと同じで、別の視点に通すと「もっともらしいが根拠の弱い部分」が見える。

### 2. 結論を「まとめ文書」として外部化する

チャットは流れて消える。数か月分の相談から、テーマごとに **結論だけ** を抜き出して保存した。

- 食事（カロリー設計・献立・減量基準）
- 睡眠と回復
- 栄養補給（トレ前後・サプリ）
- トレーニングプログラム（ベース文書）

以後のメニュー変更・負荷調整・デロード判断は、すべてベース文書を起点にする（Single Source of Truth）。

### 3. 実測データで AI の推定を較正する

AI が出す推定式（例：維持カロリー）をそのまま信じず、体重が横ばいだった週の実測から逆算して係数を決めた。→ [05-nutrition.md](nutrition.md)

## コツ

- **前提を最初に渡す**：設備・使える時間・怪我の履歴・目標 → [templates/profile.md](../templates/profile.md)
- **未指定の情報を勝手に仮定させない**：「不明な前提は仮定せず質問して」と書く
- **根拠を聞く**：「その推奨の根拠になっている研究は？」→ 急性 EMG なのか、長期の肥大研究なのかを区別する
- **出力形式を指定する**：表・Markdown にするとそのままリポジトリに入れられる
- **医療判断は任せない**：痛み・持病・数値異常は医師へ

## LLM の限界

- 数値は概算。厳密さが必要なら実測する
- 参考文献の URL や年が誤っていることがある → 公開前に一次情報を確認する
- 一般論は強いが、個人差は把握していない
