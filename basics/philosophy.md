# 00. 基本設計：身体を長期運用システムとして扱う

## 原則

1. **継続性 > 最適性**
   完璧なメニューを3週間やるより、70点のメニューを3年続ける方が強い。可用性を最優先にする。
2. **計測できないものは改善できない**
   重量・回数・RIR・体重・睡眠時間・安静時心拍を記録する。
3. **小さく変更し、1つずつ検証する**
   食事・メニュー・睡眠を同時に変えると、何が効いたか分からなくなる。1変数ずつ。
4. **障害（怪我）はもっとも高くつく**
   怪我で数週間止まると、それまでの進捗が失われる。フォームと回復を妥協しない。
5. **デフォルトを決めて意思決定を減らす**
   朝食・トレーニング時間・メニューを固定化し、毎日考えなくていい状態にする。

## 開発サイクル

```
Plan（4〜8週のブロック設計）
  → Do（実行・ログ記録）
  → Check（週次レビュー）
  → Act（重量・ボリューム・食事を調整）
```

- **スプリント** = 4〜8週間のトレーニングブロック
- **リリース** = ブロック終わりの測定（体重・主要種目の推定1RM・写真）
- **メンテナンスウィンドウ** = デロード（固定日程ではなく、疲労アラートで発火。セット数を40〜60%落とす）
- **Single Source of Truth** = [programs/6-day.md](../programs/6-day.md)。変更はすべてここを起点にする

## 計測するメトリクス

| メトリクス | 頻度 | 用途 |
| --- | --- | --- |
| 体重 | 毎朝（起床・排尿後） | 7日移動平均でトレンドを見る |
| 主要種目の重量×回数 | 毎セッション | 漸進性過負荷の確認 |
| 筋トレ量 Σ(重量×回数) | 毎セッション | 食事の計算式の入力 |
| 有酸素負荷（分 × RPE） | 毎セッション | 食事の計算式の入力・週間負荷の管理 |
| 週あたり部位別セット数 | 週次 | ボリュームの過不足 |
| 安静時心拍 | 毎朝 | 心肺機能の向上・疲労の兆候 |
| 睡眠時間・寝つき | 毎日 | 回復の最大要因 |
| 腹囲・写真 | 週1 | 体重だけでは分からない体組成の変化 |

> 日々の体重はノイズが大きい。単日の値ではなく移動平均（=トレンド）を見る。

## アンチパターン

- 毎週メニューを変える（ジャンプする前に計測できない）
- 記録しない（感覚だけで判断する）
- 睡眠を削ってトレーニング時間を作る
- 他人の上級者向けメニューをそのままコピーする
